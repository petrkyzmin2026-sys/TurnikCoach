# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## Программное изделие

**Наименование:** TurnikCoach  
**Назначение:** автономное Android-приложение для настройки упражнений, формирования тренировочного плана по текущим максимальным показателям, последовательного выполнения тренировок, контрольных замеров и анализа динамики.

## 1. Исходное состояние проекта

Рабочая ветвь: `main`.

В проекте сохранены:

- Android-приложение с локальным WebView-интерфейсом;
- модели упражнений, тренировок, подходов и статистики;
- алгоритм формирования тренировочного плана;
- статические изображения упражнений;
- сценарий сборки APK в GitHub Actions;
- сценарий проверки пользовательского интерфейса;
- звуковые сигналы таймера;
- последовательное прохождение тренировок;
- возможность пропуска тренировки;
- возможность выполнить несколько тренировок за один календарный день.

Настоящее ТЗ содержит как ранее реализованные требования, так и согласованные изменения, которые необходимо довести до готового состояния.

## 2. Общие требования

Приложение должно:

- работать на Android без обязательного подключения к сети;
- хранить настройки, ход тренировки и историю локально;
- сохранять данные после закрытия приложения, перезапуска телефона и обновления APK;
- применять настоящие интерактивные элементы; использование изображения интерфейса вместо работающего экрана запрещается;
- обеспечивать возможность установки испытательной сборки рядом с ранее установленной версией;
- не изменять завершённые записи истории после пересчёта последующих планов.

Дата и день недели применяются только для учёта. Выбор следующей тренировки по календарю запрещается.

## 3. Структура тренировочного цикла

Установить следующую последовательность этапов:

1. Тренировка 1.
2. Тренировка 2.
3. Тренировка 3.
4. Контрольный замер максимумов.
5. Тренировка 1 нового цикла.

Контрольный замер является отдельным этапом, но не является тренировкой.

После завершения или пропуска обычной тренировки счётчик этапов увеличивается. После завершения контрольного замера завершается текущий цикл и начинается следующий.

Пользователь вправе пройти несколько последовательных этапов в один календарный день. После сохранения выполненного этапа должна быть доступна кнопка запуска следующего этапа.

## 4. Раздел «Тренировка»

Существующий раздел «Упражнения» переименовать в «Тренировка».

Обеспечить:

- добавление упражнения;
- удаление упражнения;
- включение и исключение упражнения из действующей программы;
- изменение порядка упражнений;
- ввод и изменение наименования;
- ввод текущего максимального результата;
- отображение абсолютного рекорда;
- назначение статического изображения;
- настройку количества подходов;
- настройку времени отдыха;
- сохранение параметров.

План строится автоматически от текущего максимума.

При изменении текущего максимума пересчитываются только будущие планы. Завершённые записи истории остаются неизменными.

Коэффициенты и порядок прогрессии должны соответствовать исходной авторской тренировочной системе. Подмена авторского алгоритма произвольной процентной схемой запрещается.

## 5. Раздел «Сегодня»

Отображать:

- дату;
- номер текущего цикла;
- следующий этап;
- номер очередной тренировки либо надпись «Контрольный замер»;
- перечень упражнений;
- план подходов;
- выполненные в этот день этапы;
- кнопку «Начать тренировку»;
- кнопку «Начать следующую тренировку», если в этот день этап уже выполнен;
- кнопку «Пропустить тренировку».

При пропуске обычной тренировки:

- сформировать запись в журнале;
- установить состояние «Пропущено»;
- записать дату, номер цикла и номер тренировки;
- перевести последовательность на следующий этап.

## 6. Экран выполнения упражнения

В верхней части отображать:

- наименование упражнения;
- номер упражнения и общее количество упражнений;
- номер подхода и общее количество подходов;
- установленный план подходов одной строкой.

В средней части размещать одну статическую картинку упражнения.

Круглый индикатор с надписью «Сейчас сделать …» удалить полностью.

Оставить:

- надпись «ФАКТИЧЕСКИ»;
- крупное значение фактических повторений;
- кнопку уменьшения;
- кнопку увеличения.

Предусмотреть органы управления:

- «Подход выполнен»;
- «Пропустить подход»;
- «Добавить 30 секунд»;
- «Закончить отдых»;
- «Завершить тренировку».

Фактическое количество повторений не должно принимать отрицательное значение.

## 7. Досрочное завершение тренировки

При нажатии «Завершить тренировку» вывести подтверждение:

- «Завершить и сохранить»;
- «Продолжить тренировку».

При подтверждении:

- сохранить все завершённые подходы с фактическими значениями;
- сохранить оставшиеся подходы как незавершённые;
- установить состояние тренировки «Завершена досрочно»;
- рассчитать фактически выполненную сумму;
- вывести результат в журнале и графике объёма;
- перевести последовательность на следующий этап.

## 8. Таймер и звуковые сигналы

Во время отдыха отображать обратный отсчёт.

Подавать короткие предупредительные сигналы:

- при остатке 3 секунды;
- при остатке 2 секунды;
- при остатке 1 секунда.

После полного окончания упражнения подавать один отдельный продолжительный сигнал.

Сигнал окончания упражнения должен отличаться от предупредительных сигналов.

При уходе приложения в фон окончание отдыха рассчитывать по сохранённой абсолютной метке времени. После возврата отображать фактически оставшееся время.

## 9. Контрольный замер максимумов

Контрольный замер автоматически назначается после каждой третьей тренировки.

Для каждого включённого упражнения вывести:

- наименование;
- предыдущий текущий максимум;
- абсолютный рекорд;
- фактический результат;
- кнопки уменьшения и увеличения;
- кнопку «Сохранить результат»;
- кнопку «Пропустить упражнение».

Для одного упражнения выполняется одна попытка.

Правила обработки:

- сохранённый результат становится новым текущим максимумом, даже если он ниже прежнего;
- абсолютный рекорд изменяется только при превышении прежнего значения;
- при пропуске упражнения текущий максимум не изменяется;
- сохраняется сравнение «предыдущий максимум → новый максимум»;
- сохраняются дата и время замера;
- результат добавляется в график максимальных показателей.

После обработки всех включённых упражнений:

- создать отдельное событие «Контрольный замер»;
- завершить текущий цикл;
- назначить Тренировку 1 нового цикла.

## 10. Оценка нагрузки

После завершения обычной тренировки предоставить варианты:

- «Легко»;
- «Нормально»;
- «Тяжело».

Оценку сохранить в журнале. Если авторская система предусматривает корректировку последующего плана по оценке нагрузки, применять только установленное автором правило.

## 11. Раздел «История»

Разделить на вкладки:

- «Динамика»;
- «Журнал».

### 11.1. Вкладка «Динамика»

Установить общий фильтр выбора упражнения.

Вывести два самостоятельных графика.

**График «Максимальный результат»:**

- горизонтальная ось — дата;
- вертикальная ось — количество повторений;
- точки — результаты контрольных замеров;
- отдельно отображать абсолютный рекорд.

**График «Сумма за тренировку»:**

- горизонтальная ось — дата;
- вертикальная ось — сумма фактических повторений;
- данные относятся к выбранному упражнению;
- досрочно завершённая тренировка учитывается по фактической сумме;
- пропущенная тренировка не учитывается как нулевой результат.

Объединение максимума и тренировочного объёма в одном графике запрещается.

### 11.2. Вкладка «Журнал»

Для каждой записи отображать:

- дату и время;
- номер цикла;
- тип этапа;
- номер тренировки;
- состояние;
- перечень упражнений;
- плановые значения;
- фактические значения;
- сумму повторений;
- пропущенные и незавершённые подходы;
- оценку нагрузки;
- результаты контрольного замера.

Применяемые состояния:

- «Выполнена»;
- «Завершена досрочно»;
- «Пропущена»;
- «Контрольный замер выполнен»;
- «Упражнение контрольного замера пропущено».

## 13. Изображения

Для каждого упражнения применять одну статическую картинку.

Изображение должно:

- находиться внутри APK;
- работать без сети;
- не перекрывать текст и органы управления;
- иметь резервное отображение при ошибке;
- сохранять пропорции.

Картинку отжиманий восстановить и проверить на реальном экране приложения.

Анимации на текущем этапе не применять.

## 14. Навигация

- «Сегодня»;
- «История».

Все кнопки должны иметь визуальное состояние нажатия и выполнять назначенное действие.

## 15. Установка и подпись

Испытательная сборка должна иметь отдельный идентификатор пакета, например:

`ru.turnikcoach.review`

Это обеспечивает установку рядом со старой версией, подписанной другим сертификатом.

Требования:

- действительная подпись APK;
- постоянный ключ подписи последующих испытательных выпусков;
- корректный AndroidManifest;
- проверенная целостность APK;
- отсутствие требования удалять старое приложение;
- номер версии и понятное имя файла.

Ключ подписи, размещённый в открытом репозитории, нельзя применять для эксплуатационного выпуска. Перед публичным выпуском ключ требуется заменить и хранить в GitHub Secrets.

## 16. Порядок предварительного согласования

Перед каждым выпуском APK подготовить интерактивный предпросмотр.

В предпросмотре должны работать все кнопки и переходы, относящиеся к изменению.

После согласования предпросмотра выполнить полный контрольный прогон приложения.

## 17. Приёмочные испытания

Перед выдачей APK выполнить:

1. Добавление и изменение упражнения.
2. Изменение порядка упражнений.
3. Ввод текущего максимума.
4. Проверку построенного плана.
5. Полное прохождение Тренировки 1.
6. Проверку кнопок уменьшения и увеличения.
7. Пропуск подхода.
8. Добавление 30 секунд отдыха.
9. Досрочное окончание отдыха.
10. Проверку сигналов на 3, 2 и 1 секунде.
11. Проверку продолжительного сигнала окончания упражнения.
12. Досрочное завершение тренировки.
13. Проверку сохранения незавершённых подходов.
14. Полное прохождение Тренировки 2.
15. Пропуск Тренировки 3.
16. Проверку записи пропуска.
17. Запуск нескольких этапов в один календарный день.
18. Прохождение контрольного замера.
19. Сохранение результата ниже прежнего максимума.
20. Проверку снижения текущего максимума.
21. Проверку сохранения абсолютного рекорда.
22. Пропуск отдельного упражнения контрольного замера.
23. Переход к Тренировке 1 нового цикла.
24. Проверку графика максимального результата.
25. Проверку графика суммы за тренировку.
26. Проверку фильтра упражнений.
27. Проверку журнала.
28. Закрытие и повторный запуск приложения.
29. Проверку сохранности истории и очередности.
30. Установку APK на Android-устройство.
31. Нажатие всех доступных кнопок.
32. Проверку полного цикла «1 → 2 → 3 → контрольный замер → 1».

APK разрешается выдавать только после успешного выполнения полного цикла и проверки записей истории.
