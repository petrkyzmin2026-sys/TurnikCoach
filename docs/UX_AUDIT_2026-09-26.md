# Аудит UX и интерактивности TurnikCoach — 2026-09-26

## Исходные требования к интерфейсу

Проверка ведётся по пользовательским сценариям, а не только по наличию функций в коде.

Базовые критерии:
- любое видимое действие должно либо выполняться, либо быть явно недоступным с объяснением причины;
- критическое действие не должно завершаться молча;
- активная тренировка должна иметь постоянный доступ к выходу без сохранения;
- завершение основного комплекса не должно блокировать независимые дополнительные упражнения;
- после сохранения, удаления, обновления и других изменений пользователь должен получить видимую обратную связь;
- системная кнопка/жест «Назад» должны сохранять состояние или запрашивать подтверждение при риске потери данных;
- минимальная зона нажатия интерактивного элемента — 48 dp.

Ориентиры:
- Android Core App Quality: navigation, state preservation, 48 dp touch targets;
- Android accessibility: крупные и простые элементы управления;
- Android Snackbar: краткая обратная связь после операций;
- Hevy / Strong: активная тренировка остаётся управляемой, допускается выход/discard; дополнительные действия доступны в рамках живой тренировки.

## Инвентаризация кнопок

Автоматизированный статический аудит выполняется скриптом `scripts/button_static_audit.js`.

Проверяется:
- inline-обработчик ссылается на существующую функцию;
- критические функции старта тренировки существуют;
- динамические критические кнопки имеют стабильные DOM id и программные обработчики;
- собранный `live/hotfix.js` содержит тот же модуль курса, что `live/course.js`.

На момент группы 1 необъявленных обработчиков не выявлено. Основной класс дефектов — логические guard-условия, скрытые/обрезанные элементы и отсутствие обратной связи.

## Выявленные дефекты

### Критические
- Обновление 5.16.22 выполнялось без понятного пользователю подтверждения результата: нельзя было достоверно понять, пришло обновление или нет.
- После сохранения основного комплекса экран «Сегодня» прекращал сценарий и не давал начать выбранную дополнительную нетяговую тренировку.
- «Выйти без сохранения» добавлялась в контейнер `.controls` фиксированной высоты 170 px и фактически могла оказаться за пределами видимой области.
- Код искал заголовок активной тренировки по устаревшему селектору `.stageHeader`, тогда как действующий шаблон использует `.wtop`.

### Системные
- Ряд функций `tcStart*` при несоответствии состоянию выполняют молчаливый `return`. При рассинхронизации отрисовки и состояния это выглядит как «некликабельная кнопка».
- Недельные кнопки календаря имеют высоту 32 px.
- Часть собственных навигационных кнопок ранее имела 36–38 px.
- Значительная часть старого интерфейса использует inline `onclick`; для критических динамических действий переход выполняется на программные обработчики.
- Не все причины недоступности действий выведены непосредственно возле кнопки.

## План малыми группами

### Группа 1 — критический пользовательский цикл
- обновление и видимое подтверждение установленной версии;
- основной комплекс → дополнительная тренировка в тот же день;
- выход из активной тренировки без сохранения;
- отмена ошибочно сохранённой основной тренировки;
- Android WebView smoke-тест указанных действий.

### Группа 2 — все кнопки действий
- `Начать`, `Сохранить`, `Перенести`, `Подтвердить`, `Продолжить`;
- устранение молчаливых guard-возвратов;
- состояние «доступно / недоступно + причина»;
- проверка каждой ветви курса.

### Группа 3 — геометрия и навигация
- все touch-target не менее 48 dp;
- календарь, закрытие sheet, навигация, информационные кнопки;
- Back/gesture Back;
- отсутствие перекрытий и клиппинга на небольшом экране.

### Группа 4 — сохранность состояния
- сворачивание/возврат;
- сон/разблокировка;
- прерывание во время подхода и отдыха;
- обновление во время неактивной/активной тренировки;
- повторный запуск после аварийного завершения.

## Правило выпуска

Изменение не переносится в `main`, пока:
1. статический аудит не проходит без ошибок;
2. профильный Android WebView сценарий не проходит фактическими нажатиями;
3. при ошибке теста определяется причина, а не игнорируется результат.
